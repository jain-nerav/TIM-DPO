# TIM-DPO

## Token Importance Memory for Direct Preference Optimization

TIM-DPO is a token-level extension of Direct Preference Optimization (DPO) that uses a persistent **Token Importance Memory (TIM)** to adapt the contribution of individual response tokens to the preference objective.

The method maintains a vocabulary-level Token Importance Memory. During training, gradients of token embedding outputs are used to estimate token importance. These observations are aggregated by vocabulary token and incorporated into persistent memory.

The resulting memory values are converted into token weights and used to modify the token-level aggregation of log-probabilities in the DPO objective.

---

# 1. Research Objective

Standard DPO aggregates token log-probabilities into sequence-level scores without distinguishing the contribution of individual response tokens.

TIM-DPO investigates whether information contained in token-level gradients can provide a useful signal for differentiating these token contributions during preference optimization.

For a token embedding \(e_t\), the gradient is

$$
g_t = \frac{\partial L}{\partial e_t}.
$$

The primary TIM-DPO importance measure is the squared L2 norm:

$$
c_t = \|g_t\|_2^2.
$$

A plain L2 norm is evaluated as an ablation:

$$
c_t = \|g_t\|_2.
$$

These position-level importance observations are aggregated by vocabulary token and stored in the Token Importance Memory.

---

# 2. Method Overview

The core TIM-DPO training cycle is:

```text
Previous Token Importance Memory
              ↓
      Current token weights
              ↓
        DPO forward pass
              ↓
           DPO loss
              ↓
         Backward pass
              ↓
     Embedding-output gradients
              ↓
      Per-position importance
              ↓
   Aggregate by vocabulary token
              ↓
      Process observations
              ↓
     Update Token Importance Memory
              ↓
       Optimizer parameter update
```

The ordering is important.

**Information from the current batch is not used to weight that same batch.** The weights applied to a batch are obtained from the importance memory available before that batch is processed. The gradients generated by the batch are then used to update the memory for subsequent batches.

TIM is a **first-order auxiliary mechanism**. Importance observations are detached from the computation graph and are not used to construct a second-order optimization objective.

---

# 3. Token Importance Memory

TIM maintains one importance estimate for every vocabulary token:

$$
I_v.
$$

All vocabulary tokens are initially assigned the same importance:

$$
I_v^{(0)} = 1.
$$

The primary memory mechanism is an exponential moving average:

$$
I_v^{(t)}
=
\beta I_v^{(t-1)}
+
(1-\beta)\hat{c}_v^{(t)},
$$

where:

* \(I_v^{(t)}\) is the stored importance of vocabulary token \(v\),
* \(\beta\) is the EMA decay coefficient,
* \(\hat{c}_v^{(t)}\) is the processed importance observation for token \(v\) in the current batch.

A larger \(\beta\) gives greater influence to historical observations and produces slower, more stable updates. A smaller \(\beta\) makes the memory respond more quickly to recent observations.

Tokens that are not observed in a batch retain their existing memory values.

---

# 4. Importance Estimation

## 4.1 Embedding gradients

TIM captures gradients of the **token embedding outputs** during backpropagation.

For each token position:

$$
g_t = \frac{\partial L}{\partial e_t}.
$$

The gradient is a position-level signal. The implementation subsequently associates each gradient observation with its corresponding vocabulary token ID.

TIM supports two importance metrics.

### Squared L2

The primary configuration uses:

$$
c_t = \|g_t\|_2^2
=
\sum_j g_{t,j}^2.
$$

### L2

The corresponding ablation uses:

$$
c_t = \|g_t\|_2.
$$

Comparing these metrics tests whether the squared magnitude of the gradient provides a meaningfully different signal from its unsquared magnitude.

---

# 5. Token Aggregation

The same vocabulary token can occur multiple times within a training batch.

Before updating TIM, repeated occurrences of a token are aggregated by their mean importance:

$$
\hat{c}_v
=
\frac{1}{n_v}
\sum_{i=1}^{n_v} c_{v,i}.
$$

Thus, each observed vocabulary token receives one importance observation per batch rather than multiple sequential memory updates.

This prevents frequent occurrences of the same token within a single batch from receiving disproportionate influence merely because the token appeared more times.

The resulting memory remains **vocabulary-level rather than contextual**. Different tokenizer vocabulary IDs are treated as distinct tokens even if their decoded text is similar.

---

# 6. Batch Importance Normalization

TIM optionally normalizes the token-level importance observations within each batch.

When enabled, observations are divided by their batch mean:

$$
\hat{c}_v
=
\frac{c_v}
{\operatorname{mean}(c)}.
$$

This places observations on a more consistent scale across batches and gives them an approximately unit mean before they are incorporated into memory.

Batch normalization is evaluated as an ablation.

---

# 7. Importance Clipping

TIM optionally clips individual importance observations before they are incorporated into the memory.

The clipping operation is:

$$
c_v
=
\operatorname{clip}
(c_v,c_{\min},c_{\max}).
$$

Clipping is applied to the importance observation itself rather than to the final token weight.

This limits the influence of unusually large or small gradient-derived observations on subsequent memory updates.

Clipping can be enabled or disabled as an ablation.

---

# 8. EMA Memory

The primary TIM-DPO configuration uses persistent EMA memory.

For an observed vocabulary token:

$$
I_v^{(t)}
=
\beta I_v^{(t-1)}
+
(1-\beta)\hat{c}_v^{(t)}.
$$

For an unobserved token:

$$
I_v^{(t)} = I_v^{(t-1)}.
$$

This gives each observed token a persistent history across training rather than basing its weight solely on the most recent batch.

---

# 9. Previous-Batch Memory

TIM also supports a non-EMA memory mode:

```python
memory_mode="previous_batch"
```

In this configuration, the current processed observation replaces the previous stored value for an observed token:

$$
I_v^{(t)} = \hat{c}_v^{(t)}.
$$

This removes the temporal smoothing provided by the EMA.

The comparison between EMA and previous-batch memory tests whether persistent historical information contributes beyond using only recent observations.

---

# 10. Token Weight Retrieval

Stored TIM values are converted into token weights when the DPO sequence scores are calculated.

The retrieval process is:

```text
Token Importance Memory
          ↓
Optional log compression
          ↓
Normalization
          ↓
Token weights
```

With mean normalization, the conceptual transformation is:

$$
w_t
=
\frac{I_t}{\mu_I}.
$$

Consequently:

* above-average importance produces weights above 1,
* below-average importance produces weights below 1,
* the average retrieved weight is approximately 1.

Previously unseen vocabulary tokens retain the neutral weight of 1.0.

The retrieved weights are detached from the computation graph. They therefore influence the DPO loss without creating a second-order gradient path through the importance-estimation mechanism.

---

# 11. Log Compression

TIM supports optional logarithmic compression:

$$
I'_v = \log(1+I_v).
$$

The purpose is to reduce the dominance of extremely large importance values while preserving their ordering.

The two configurations are:

```text
No compression:

I → normalization → weights
```

and:

```text
Log compression:

I → log(1 + I) → normalization → weights
```

Log compression is evaluated as an ablation.

---

# 12. DPO Integration

TIM-DPO modifies the token-level aggregation used to obtain the sequence scores entering the DPO objective.

The autoregressive model produces token-level log-probabilities:

$$
\log \pi(y_t \mid y_{<t},x).
$$

TIM provides corresponding token weights:

$$
w_t.
$$

The weighted token contribution is:

$$
w_t\log\pi(y_t\mid y_{<t},x).
$$

These weighted contributions are then summed to obtain the sequence-level score used by the DPO objective.

The token weights therefore modify **how token log-probabilities contribute to the sequence score**. They do not redefine the underlying model probability distribution.

---

# 13. Response Positions and Causal Alignment

TIM weighting is applied to the token positions that contribute to the DPO response score.

Prompt tokens provide context for the model and therefore influence the resulting gradients and response probabilities, but prompt tokens are not treated as TIM update targets.

Because an autoregressive language model predicts the next token, embedding positions and target labels require a one-token shift.

Conceptually:

```text
Embedding position t
        ↓
gradient at position t
        ↓
prediction for target token t + 1
```

Therefore, the implementation aligns the embedding-gradient importance at position \(t\) with the vocabulary ID of the target token at position \(t+1\).

This alignment ensures that an importance observation is associated with the token whose log-probability is being evaluated.

EOS is excluded from the TIM memory update.

# 14. Configuration

TIM-DPO centralizes its algorithmic settings in `TIMConfig`.

The primary configuration is represented by:

```python
from config import TIMConfig

config = TIMConfig(
    memory_mode="ema",
    beta=0.99,
    initial_importance=1.0,
    importance_metric="l2_squared",
    clip_importance=True,
    clip_min=0.25,
    clip_max=4.0,
    normalize_batch_importance=True,
    eps=1e-8,
    compression="none",
    normalization="mean",
)
```

## Configuration parameters

| Parameter                    | Description                                      |
| ---------------------------- | ------------------------------------------------ |
| `memory_mode`                | `ema` or `previous_batch`                        |
| `beta`                       | EMA decay coefficient                            |
| `initial_importance`         | Initial importance assigned to vocabulary tokens |
| `importance_metric`          | `l2` or `l2_squared`                             |
| `clip_importance`            | Enables or disables importance clipping          |
| `clip_min`                   | Lower clipping threshold                         |
| `clip_max`                   | Upper clipping threshold                         |
| `normalize_batch_importance` | Enables batch-level importance normalization     |
| `eps`                        | Numerical stability constant                     |
| `compression`                | `none` or `log`                                  |
| `normalization`              | `none` or `mean`                                 |

These parameters define the current TIM-DPO algorithm and its finalized ablation controls.

# 19. Evaluation Pipeline

Evaluation is separated from training.

A trained checkpoint is loaded independently, responses are generated using batched inference, and the resulting outputs are passed to benchmark-specific evaluation procedures.

The general pipeline is:

```text
Trained checkpoint
        ↓
Model + tokenizer
        ↓
Benchmark prompts
        ↓
Batched generation
        ↓
Saved model responses
        ↓
Benchmark-specific evaluation
        ↓
Results
```

The evaluation pipeline does not require the DPO reference model used during preference training.

Generation and benchmark scoring are separated so that generated outputs can be inspected, reused, and evaluated independently.

# 20. Core Benchmarks

The current external benchmark suite consists of three primary evaluations.

## 20.1 XSTest

XSTest evaluates whether a model can distinguish between benign requests and unsafe requests with superficially similar characteristics.

It is particularly useful for measuring **over-refusal**.

For TIM-DPO, this benchmark is important because stronger safety behaviour should not simply result in indiscriminate refusal of benign requests.

The evaluation uses the official XSTest prompt set and its classification framework.

---

## 20.2 HarmBench

HarmBench evaluates model behaviour on harmful requests and provides a safety-focused measure of resistance to harmful instruction following.

The project uses the official HarmBench behaviour data and classifier framework.

---

## 20.3 AlpacaEval 2.0

AlpacaEval 2.0 evaluates general instruction-following quality outside the specifically safety-focused benchmarks.

This provides a measure of whether safety-oriented preference optimization is accompanied by changes in general response quality.

The evaluation uses AlpacaEval's official evaluation procedure and model judging configuration.

# 22. Held-Out Preference Evaluation

In addition to external benchmarks, trained models are evaluated on a fixed held-out preference dataset.

The evaluation split is constructed deterministically from the same source datasets used for training, while remaining disjoint from the training examples.

The evaluator reports:

* Preference accuracy
* Mean chosen reward
* Mean rejected reward
* Mean reward margin

The reference-relative reward for response \(y\) is:

$$
r(x,y)
=
\beta
\left(
\log\pi_{\text{policy}}(y\mid x)
-
\log\pi_{\text{reference}}(y\mid x)
\right).
$$

Preference accuracy is the fraction of examples for which the chosen response receives a larger reference-relative reward than the rejected response.

Metrics are also reported by source dataset.

This evaluation provides a direct measure of preference-learning behaviour independently of the external safety and general-capability benchmarks.

# 27. Training

The primary TIM-DPO training entry point is:

```text
main.py
```

A training run:

1. Loads the base model.
2. Loads the tokenizer.
3. Loads the balanced preference-training dataset.
4. Initializes `TIMConfig`.
5. Initializes `TokenImportanceMemory`.
6. Registers the embedding-gradient hook.
7. Initializes the DPO trainer.
8. Processes preference-training batches.
9. Applies TIM weights based on the memory available before each batch.
10. Computes the DPO loss.
11. Captures embedding-output gradients during backpropagation.
12. Calculates token-level importance observations.
13. Aggregates observations by vocabulary token.
14. Updates the Token Importance Memory.
15. Continues training using the updated memory for subsequent batches.
16. Saves the trained checkpoint and tokenizer.
17. Runs held-out preference evaluation.

The exact model, dataset size, training budget, and hardware configuration are defined by the current training entry point.

# 33. Research Question

The central research question is:

> **Can gradient-derived, persistent token importance provide a useful mechanism for token-level preference optimization, and how does this affect safety behaviour, over-refusal, general instruction following, and preference optimization?**

TIM-DPO approaches this question through:

$$
\boxed{
\text{Embedding Gradients}
\rightarrow
\text{Token Importance}
\rightarrow
\text{Persistent Memory}
\rightarrow
\text{Adaptive DPO Weighting}
}
$$

The experimental design then separates the contribution of the individual components through controlled ablations and evaluates the resulting models across safety, over-refusal, general instruction following, and held-out preference metrics.
